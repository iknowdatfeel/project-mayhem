# ТЗ: исправления по ревью Project Mayhem

Документ для агента, который будет вносить правки. Составлен по ревью коммита `72f5b29` (ветка `main`). Номера строк указаны для этого коммита; после первых правок они сдвинутся, поэтому у каждого пункта есть «якорь» — строка, которую можно найти поиском.

## 0. Как работать с этим документом

1. Сначала прочитай разделы 1–2 (контекст и ограничения). Без них легко сломать роутер с 128 МБ ОЗУ или совместимость с ucode 24.10.
2. Задачи сгруппированы по приоритету: **P0** → **P1** → **P2** → **P3**. Выполняй в этом порядке.
3. Задачи из раздела **D** (решение владельца) **не делай**, пока владелец не выберет вариант. Если выбор не получен — пропусти и перечисли их в отчёте.
4. Одна задача — один коммит. Формат сообщений как в истории репозитория: `fix: …`, `fix(luci): …`, `perf: …`, `refactor: …`, `test: …`, `docs: …`.
5. В каждой задаче есть «Критерии приёмки» и «Тесты». Задача считается сделанной, только когда добавлен тест (если он указан) и проходит весь `tests/run.sh`.
6. В конце пришли отчёт: какие задачи сделаны, какие пропущены и почему, вывод тестов (сводка), открытые вопросы.

## 1. Контекст проекта

Маршрутизация трафика для OpenWrt на базе Xray. Два пакета:

| Пакет | Что внутри |
| --- | --- |
| `mayhem/` | init-скрипты, shell (`lib.sh`, `scheduler`, `xray-run`, CLI `mayhem`), ucode-генератор и фоновые проверки |
| `luci-app-mayhem/` | rpcd-плагин на ucode (`luci.mayhem`), `call.uc`, `warm.uc`, LuCI JS |

### Как это работает

- `/etc/init.d/mayhem start|reload` → `ucode gen.uc` (`model.uc` читает UCI и состояние системы, `build.uc` строит конфиги) → файлы в `/var/run/mayhem` (tmpfs, т.е. ОЗУ): `xray.json`, `xray.key`, `nft.conf`, `dnsmasq.conf`, `nodes.json`, `env`, `tunnels`, `overrides`…
- procd запускает `usr/libexec/mayhem/xray-run`: стартует xray, ждёт портов, ставит перехват (`mayhem_net_up`), переключает dnsmasq.
- procd запускает `usr/libexec/mayhem/scheduler`:
  - каждые 20 с — `health.uc` (внутри `mayhem.fallback`): проверка серверов и удалённого DNS;
  - каждую минуту в фоне — `downloads()`: `sub.uc update`, `update.uc due`, при изменениях `reload`;
  - каждую минуту в фоне — `minute_jobs()`: туннели, сторож, сброс памяти xray, свёртка `conn.log`.
- Если xray уже работает, новые серверы применяются без перезапуска через `live.uc` (`xray api ado/rmo/adrules/bo`).
- rpcd-плагин `luci.mayhem` загружается в **постоянный** процесс rpcd: кэши на уровне модуля в нём живут между вызовами. Методы из списка `APART` (`luci.mayhem`, якорь `const APART = [`) выполняются в **отдельном процессе** через `call.uc` — кэши уровня модуля там бесполезны.
- Дашборд опрашивает `dashboard` каждые 3 с; окно «Активные подключения» вызывает `connections` каждые 3 с.

### Ключевые файлы

| Файл | Роль |
| --- | --- |
| `mayhem/files/usr/share/mayhem/lib.sh` | общие shell-функции: nft, туннели, сторож, dnsmasq, блокировки |
| `mayhem/files/usr/libexec/mayhem/scheduler` | фоновый цикл |
| `mayhem/files/usr/libexec/mayhem/xray-run` | обёртка xray под procd |
| `mayhem/files/usr/share/mayhem/{gen,health,live,sub,update,why,migrate,fallback}.uc` | скрипты |
| `mayhem/files/usr/share/ucode/mayhem/*.uc` | модули: `build`, `model`, `links`, `rules`, `geo`, `check`, `metrics`, `fallback`, `ping`, `awg`, `runstate`, `const` |
| `luci-app-mayhem/root/usr/share/rpcd/ucode/luci.mayhem` | rpcd-бэкенд (~4500 строк) |
| `luci-app-mayhem/root/usr/share/mayhem-luci/{call,warm}.uc` | вызовы в отдельном процессе, фоновый URL-тест |
| `luci-app-mayhem/htdocs/luci-static/resources/…` | LuCI JS |
| `tests/` | тесты; `tests/run.sh` — главный раннер |

## 2. Ограничения и правила

### Целевая платформа

- OpenWrt 24.10 (opkg) и 25.12+ (apk). Архитектуры: aarch64, arm, **mips/mipsel/mips64**, x86_64, i386, riscv64. **Никаких констант, зависящих от архитектуры** (номера errno, размеры структур).
- Shell — **busybox ash**. Нельзя bash-измы (`[[ ]]`, массивы, `${var//}` и т.п.). `local` можно. awk — **busybox awk** (без расширений gawk).
- ucode — версии из OpenWrt 24.10, 25.12 и master. Старый ucode требует `;` после `export function f() { … };` и **не понимает** сокращённые методы объектов `name() {}` — используй `name: function() {}`.
- LuCI JS минифицируется LuCI-шным `jsmin` — тест `JS survives jsmin` должен проходить.

### Ресурсы роутера

- 128 МБ ОЗУ — реальная целевая конфигурация. `/tmp` и `/var/run` — это ОЗУ.
- Каждый запуск бинаря xray (`xray api …`, `xray version`) — это ещё ~30 МБ на секунду. Не добавляй новых.
- Не запускай процессы в циклах, если можно одним процессом.
- Флеш: писать только когда данные изменились.
- rpcd обслуживает все вызовы LuCI в одном процессе: **в rpcd нельзя ждать процессы**. Используй `deferred_sh()` или добавь метод в `APART`.

### Стиль

- Комментарии в коде — на английском, в стиле существующих: объясняют «почему».
- Строки интерфейса — только через `_('…')` с русским переводом в `luci-app-mayhem/po/ru/mayhem.po`. После изменения строк: `python3 tools/i18n.py pot` и `python3 tools/i18n.py check`.
- Если меняется видимое поведение — обнови `README.md`.

### Тесты

Локальная сборка ucode (как в CI, `.github/workflows/build.yml`):

```sh
sudo apt-get install -y cmake libjson-c-dev nftables shellcheck unzip
git clone --depth 1 https://github.com/openwrt/libubox.git /tmp/libubox
cmake -S /tmp/libubox -B /tmp/libubox/build -DBUILD_LUA=OFF -DBUILD_EXAMPLES=OFF
sudo cmake --build /tmp/libubox/build --target install -j4

cmake -S /tmp/uci -B /tmp/uci/build -DBUILD_LUA=OFF
sudo cmake --build /tmp/uci/build --target install -j4
sudo ldconfig
sudo sh tests/build-ucode.sh 24.10 /opt/ucode-24.10
# xray той версии, что в mayhem/files/usr/share/mayhem/const.sh (MAYHEM_XRAY_VERSION)
```

Запуск:

```sh

```

- Перед финальным отчётом прогони с ucode 24.10, 25.12 и master (как в CI).
- LuCI-тесты в браузере: `UCODE=ucode sh tests/luci/run.sh /path/to/luci` (Playwright + Chromium).
- Новые shell-тесты добавляй в список shellcheck в `tests/run.sh` (якорь `shellcheck -s sh -f gcc`) и в сам раннер.
- ucode-тесты пишутся как `tests/ping.uc`: печатают строку на каждое нарушенное ожидание, пустой вывод — успех.

### P0 — безопасность и сломанная функциональность

#### P0-1. XSS в LuCI через данные подписки

- **Где:**
  - `htdocs/luci-static/resources/view/mayhem/dashboard.js:917` — `E('b', n.name)`;
  - `htdocs/luci-static/resources/mayhem/dash/chain.js:151`, `:226` — имена серверов в цепочке;
  - `htdocs/luci-static/resources/mayhem/common.js:331` — `ipSpan()`: первая отрисовка через `E('span', {…}, ipText(text))`;
  - `htdocs/luci-static/resources/mayhem/page/sections.js:1204`, `:1207` — `x.error`;
  - все вызовы `ui.addNotification(null, E('p', r.error|e.message), …)` (около 20 мест, ищи `E('p', r.error` и `E('p', e.message`).
- **Проблема:** в LuCI `E(tag, attrs, 'строка')` и `E(tag, 'строка')` кладут строку в `innerHTML` (`luci.js`, `dom.append`: не-Node и не-массив → `node.innerHTML = …`). Массив строк, наоборот, превращается в текстовые узлы. Имя сервера целиком задаёт провайдер подписки; адрес сервера проходит `parse_url` в `links.uc` с символами `<>=` и пробелами, а в JSON-подписках он вообще произвольный. Вредоносная подписка или MITM на http-подписке выполняет JS в сессии администратора, то есть получает полный контроль над роутером через ubus.
- **Что сделать:**
  1. Добавь в `mayhem/common.js` хелпер, например `text(v)`, который возвращает `[ String(v ?? '') ]` (массив → текстовые узлы) или `document.createTextNode(...)`.
  2. Пройди **все** вызовы `E(` во всех JS-файлах пакета. Для каждого строкового потомка реши: это литерал или перевод без динамических данных (оставить) либо данные с роутера или из сети (обернуть).
  3. Строки вида `_('… %s …').format(dyn)` с недоверенным `dyn` — тоже недоверенные: оборачивай результат целиком.
  4. Ошибки бэкенда (`r.error`, `e.message`) считай недоверенными: в них бывают тексты curl, xray и имена из подписок.
  5. Проверь подписи вариантов в `form.ListValue/MultiValue/DynamicList` (`o.value(key, label)`) и `ui.Dropdown`: если `label` динамический (имена серверов, подписок, туннелей, категорий), передавай текст безопасно. Dropdown рисует подписи через `E()`.
  6. Проверь `ui.showModal(title, …)` с динамическим `title`.
  7. В `ipSpan()` первая отрисовка должна идти через текстовый узел, как и обновление в `ipRefresh()`.
- **Критерии приёмки:**
  - Сервер с именем `<img src=x onerror="window.__mhxss=1">` и адресом `<img src=x onerror=window.__mhxss=2>` отображается на дашборде, в окне цепочки, в выпадающих списках и в уведомлениях как текст.
  - `window.__mhxss` остаётся `undefined`.
  - Статичные переводы с разметкой (если такие есть) выглядят как раньше.
- **Тесты:** в `tests/luci/run.sh` добавь в фикстуру `subs/mysub.json` узел с таким именем, а в `tests/luci/harness.py` после открытия дашборда и окна цепочки — проверку `pg.evaluate('window.__mhxss === undefined')` и что имя видно в `innerText`.
- **Заметки:** атрибуты (`title`, `value`, `data-*`) задаются через `setAttribute` — они безопасны.

#### P0-2. TCP-пинг не работает на MIPS

- **Где:** `mayhem/files/usr/share/ucode/mayhem/ping.uc:173` (якорь `socket.error(true) != 115`) и `:218` (якорь `err == 111`).
- **Проблема:** захардкожены `EINPROGRESS = 115` и `ECONNREFUSED = 111` — это значения x86/ARM. На MIPS они равны 150 и 146. В результате каждое неблокирующее подключение считается неудачным и все серверы получают «no connection». Резервный путь через curl в `probe`/`probe_tcp` (`luci.mayhem`) не включается, потому что `tcp_ping` вернул объект, а не `null`.
- **Что сделать:**
  1. После `s.connect(…)` не проверяй errno. Если `connect` вернул `null`, всё равно добавляй сокет в `open` и жди `POLLOUT`; результат определяй только по `SO_ERROR` (это уже делается в цикле poll).
  2. Чтобы отличать «refused» от остальных ошибок, не сравнивай с числом. Возьми константу из модуля socket, если она там есть (`socket.ECONNREFUSED` или аналог — проверь в исходниках ucode 24.10), иначе считай любую ненулевую `SO_ERROR` ошибкой `no connection`, а `refused` выводи только при наличии константы.
  3. Поищи по всему репозиторию другие числовые errno: `grep -rnE "error\(true\)|== 1[0-9]{2}\b"`.
- **Критерии приёмки:** на x86 поведение `tests/ping.uc` не меняется. В коде нет числовых errno.
- **Тесты:** `tests/ping.uc` — дополни проверкой, что открытый порт даёт `ms`, закрытый — ошибку, а «молчащий» хост — `timeout`. По возможности: отдельный job в CI с запуском `tests/ping.uc` в `qemu-mips` на ucode, собранном под mips (см. P3-10).

#### P0-3. Флеш читается каждую минуту после перезагрузки (`sub.uc`)

- **Где:** `mayhem/files/usr/share/mayhem/sub.uc`, функция `update()`, около `:440-460` (якорь `if (is_fresh)`).
- **Проблема:** состояние `subs-state.json` лежит в ОЗУ и после перезагрузки пусто. Первая быстрая проверка (`st.url == sub.url && st.updated …`) не срабатывает, читается кэш подписки с флеша (сотни КБ JSON), он оказывается свежим, и выполняется `continue` **без записи `state[sn]`**. Так продолжается каждую минуту до конца интервала обновления — при 12 ч это до 720 разборов на подписку.
- **Что сделать:** перед `continue` в ветке `is_fresh` (и в ветке «повтор позже после ошибки», если она тоже уходит в `continue`) заполни `state[sn]` из кэша: `url = cache.url`, `updated = max(cache.updated, st.updated)`, `info = cache.info`, если её нет. Проследи, что `write_json(STATE_FILE, state)` в конце запишет это.
- **Критерии приёмки:** после «перезагрузки» (удалён `subs-state.json`) первый вызов `sub.uc update --no-wait` читает кэш один раз, второй вызов кэш с флеша не читает.
- **Тесты:** добавь проверку в shell-тест подписок (например, `tests/serverlist.sh` или новый `tests/substate.sh`). Подложи свежий кэш, удали состояние, запусти `update` дважды. Второй запуск проверь через `strace -e openat`, если он есть, либо через подмену `MAYHEM_SUBS_DIR` на каталог, где файл после первого запуска заменён битым JSON: второй запуск не должен на него реагировать.

### P1 — баги корректности

#### P1-1. Планировщик не обрабатывает TERM, пока идёт `health.uc`

- **Где:** `mayhem/files/usr/libexec/mayhem/scheduler:137-138` (якорь `bounded 120 env MAYHEM_TICK`).
- **Проблема:** `health.uc` запускается в foreground, а ash выполняет trap только после его завершения. Если сервер не отвечает, прогон длится не меньше 9 с, а procd по умолчанию ждёт 5 с (`term_timeout`) и затем убивает планировщик через SIGKILL. Дети (`downloads` с curl, `minute_jobs`, `health.uc`) остаются сиротами; `health.uc` может после остановки вызвать `xray api bo`, записать `health.json` и `mayhem_dns_servers`.
- **Что сделать:** запускай `health.uc` так же, как `nap()`: в фоне, сохраняя pid в переменную (`hc_pid`), затем `wait "$hc_pid"`. В `on_term` добавь `kill "$hc_pid"`. Кроме того, задай `procd_set_param term_timeout 10` для инстанса `scheduler` в `etc/init.d/mayhem`, чтобы было время доделать.
- **Критерии приёмки:** TERM во время долгого прогона `health.uc` завершает планировщик за доли секунды, без живых потомков.
- **Тесты:** расширь `tests/scheduler.sh`. Подмени `health.uc` скриптом с `sleep 30`, пошли TERM, проверь, что через 1–2 с не осталось ни планировщика, ни `sleep`.

#### P1-2. Гонка блокировки в `update.uc`

- **Где:** `mayhem/files/usr/share/mayhem/update.uc:200-227` (функция `lock()`).
- **Проблема:** каталог блокировки, уже созданный другим процессом, у которого ещё нет файла `pid` (окно между `mkdir` и `writefile`), считается брошенным и удаляется. В итоге два `update.uc` работают одновременно и вместе пишут гео-файлы и `data-state.json`.
- **Что сделать:** минимально — перенеси логику из `sub.uc` (`lock()`): блокировку без pid считать брошенной только если `mtime` старше 10 с, а снимать чужую только если в ней всё ещё тот же pid. Правильнее — сделать P3-1 (общий модуль блокировок) и использовать его здесь.
- **Критерии приёмки:** два параллельных `update.uc geo` никогда не работают одновременно; второй выходит с кодом 4 (`busy`).
- **Тесты:** `tests/locks.sh` — дополни случаем «каталог блокировки есть, pid ещё нет»: свежий каталог не должен удаляться, а каталог старше 10 с — должен.

#### P1-3. Старый формат `ss://BASE64(...)` портит пароль

- **Где:** `mayhem/files/usr/share/ucode/mayhem/links.uc:398-445`, функция `parse_ss` (якоря `u.user = urldecode(u.user)` и `let ui = urldecode(u.user)`).
- **Проблема:** в старом формате расшифрованная строка `method:password@host:port` содержит пароль как есть, без URL-кодирования. Код же прогоняет его через `urldecode` дважды: `%41` в пароле превращается в `A`. Кроме того, символы `?`, `#` и `/` в сыром пароле ломают `parse_url`.
- **Что сделать:** старый формат разбирай отдельно, без `parse_url`: регулярное выражение вида `^([^:]+):(.*)@(\[[^\]]+\]|[^:@]+):([0-9]+)$` по расшифрованной строке (метод — до первого `:`, хост и порт — после **последнего** `@`), без `urldecode`. Имя бери из фрагмента исходной ссылки. Формат SIP002 не трогай.
- **Критерии приёмки:** ссылка `ss://` + base64(`aes-256-gcm:p%41ss?x#y@1.2.3.4:8388`) + `#name` даёт `method=aes-256-gcm`, `password=p%41ss?x#y`, `address=1.2.3.4`, `port=8388`, `name=name`.
- **Тесты:** добавь случаи в `tests/links.uc`.

#### P1-4. Переименование vmess-сервера без добивки base64

- **Где:** `luci-app-mayhem/root/usr/share/rpcd/ucode/luci.mayhem:582`, функция `rename_link` (якорь `b64dec(replace(replace(substr(link, 8)`).
- **Проблема:** встроенный `b64dec` требует добивки `=` (поэтому в `links.uc` есть терпимый `b64()`). vmess-ссылки без `=` встречаются часто — они молча не переименовываются.
- **Что сделать:** экспортируемый `b64` из `mayhem.links` уже есть — импортируй его в плагин и используй вместо `b64dec(replace(…))`. Проверь, нет ли в rpcd других мест с `b64dec` для данных из ссылок.
- **Критерии приёмки:** vmess-ссылка без добивки переименовывается, а новое имя читается через `parse_link`.
- **Тесты:** добавь в `tests/rename.uc`.

#### P1-5. `regexp:`-правила не проверяются

- **Где:** `mayhem/files/usr/share/ucode/mayhem/rules.uc:257` (`norm_domain`, `case 'regexp':`).
- **Проблема:** правило отправляется в xray как есть. Одно выражение, которое не принимает Go RE2 (lookahead `(?=`, `(?!`, `(?<=`, обратные ссылки `\1`, possessive-квантификаторы), не даёт xray запуститься — и Mayhem перестаёт работать целиком.
- **Что сделать:** в `norm_domain` возвращай `{ error }` для выражений, где есть заведомо неподдерживаемые RE2 конструкции (`(?=`, `(?!`, `(?<=`, `(?<!`, `\1`–`\9`, `*+`, `++`, `?+`), а также для тех, что не компилирует `regexp()` в ucode. Последний критерий примени осторожно: синтаксис POSIX ERE отличается от RE2, поэтому если отказы на валидных для RE2 выражениях встречаются часто — оставь только явный список. Ошибка уже превращается в предупреждение «…, skipped» в `collect_rules`.
- **Критерии приёмки:** секция с правилом `regexp:^(?!ads).*$` получает предупреждение, xray стартует без этого правила. Обычные `regexp:` работают как раньше.
- **Тесты:** `tests/entries.uc` или `tests/links.uc` (проверки `norm_domain`), плюс проверка в `tests/run.sh`, что сгенерированный конфиг принимается `xray run -test`.

Он один раз читает `nft -j list table inet mayhem` (JSON), сравнивает строки `nftset=` и печатает `add element …`. - **Критерии приёмки:** вывод совпадает с текущим на существующих тестах. При 5000 строках `nftset=` время работы растёт линейно.

- **Проблема:** одинаковые хелперы скопированы по файлам: `read_json` — в 9 файлах, `q()` — в 9, mkdir-блокировки — в 6 (`health.uc:129-167`, `live.uc:133-168`, `sub.uc:379-413`, `update.uc:200-227`, `ucode/mayhem/fallback.uc:123-151`, `runstate.uc:15-71`) с разной логикой «брошенной» блокировки. `is_applying` есть в трёх местах (`health.uc`, `fallback.uc`, rpcd `applying()`), запись через временный файл и переименование — в каждом файле своя.
- **Что сделать:**
  1. Создай `usr/share/ucode/mayhem/util.uc` с функциями `read_json(path)`, `write_atomic(path, data)` (временный файл с pid и `rename`), `q(s)`, `log(msg, level)`, `lock(dir, { wait_ms, stale_s })` / `unlock(dir)` (одна реализация: pid-файл, «брошенная» = процесс умер или блокировка без pid старше `stale_s`, снимать только при совпадении pid), `is_applying(run_dir)`, `my_pid()`.
  2. Переведи на модуль все перечисленные файлы. Сохрани имена каталогов блокировок: их же проверяют shell и тесты.
  3. Shell-блокировки (`flock` в `lib.sh`) не трогай.
- **Критерии приёмки:** все тесты проходят. Дубликатов перечисленных функций нет (проверка `grep`).
- **Тесты:** новый `tests/util.uc` (блокировка, брошенная блокировка, блокировка без pid, атомарная запись).
- **Заметки:** `util.uc` входит в rpcd-плагин через `import` и в `call.uc` — проверь сборку `.ucc` и ucode 24.10.

#### P3-2. «Поколение» соединений подставляется в трёх местах

- **Где:** `build.uc:736-744` (`apply_generation`), `lib.sh:194-195` (`mayhem_net_generation`), `lib.sh:301-302` (`mayhem_hold_save`).

#### P3-3. Динамические nft-наборы обнуляются при каждом применении

- **Где:** `build.uc:393` (якорь `` `table inet ${C.NFT_TABLE}\ndelete table inet `` ) и `lib.sh` `mayhem_nft_kept`.
- **Проблема:** таблица пересоздаётся целиком, поэтому наборы, которые заполнил dnsmasq, теряются. Их выгружают разбором текстового вывода `nft list set` и загружают обратно.
- **Что сделать:** как минимум — P2-3 с `nft -j`. Как исследование — прототип «инкрементального» применения в одной транзакции: `add table`, `add set` (идемпотентно) для динамических наборов, `flush set` и новые элементы для статических, `flush chain` и новые правила для цепочек, `delete set` для исчезнувших. Опиши в отчёте, что ломается (смена типа или флагов набора, порядок удаления) и стоит ли переходить.
