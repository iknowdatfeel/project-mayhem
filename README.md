Маршрутизация трафика для OpenWrt на базе [Xray](https://github.com/XTLS/Xray-core): нужное идёт через прокси или туннель, остальное — напрямую; в глобальном режиме через прокси идёт всё, кроме исключений. Интерфейс в LuCI на русском и английском, установка одной командой.

## Требования

- OpenWrt 24.10 (opkg) или 25.12 и новее (apk).
- Около 40 МБ свободной флеш-памяти: сам xray весит ~36 МБ в распакованном виде.
- 128 МБ ОЗУ и больше; рекомендуется 256 МБ.
- Архитектуры: aarch64, arm (v5–v7), mips, mipsel, mips64, x86_64, i386, riscv64.

## Установка

```sh
wget -qO /tmp/mayhem-install.sh https://raw.githubusercontent.com/iknowdatfeel/project-mayhem/main/install.sh && sh /tmp/mayhem-install.sh && rm -f /tmp/mayhem-install.sh
```

- Установщик проверяет версию OpenWrt и свободное место, ставит пакеты `mayhem` и `luci-app-mayhem`, предлагает русский язык интерфейса, скачивает официальный xray нужной архитектуры (с проверкой SHA-256) и оставляет Mayhem выключенным. Повторный запуск обновляет установленную версию.
- Установщик и обновление из меню заменяют dnsmasq на dnsmasq-full (nftset для обхода и туннелей в ядре); если замена не удалась, остаётся прежний dnsmasq.
- Ставится и включается TCP BBR для соединений роутера (через них xray ходит к своим серверам). Если модуля в прошивке нет, всё остаётся как было (`mayhem bbr`).
- AmneziaWG ставится из «Настройки → Обновление компонентов» или `mayhem awg-install` (пакеты сверяются с SHA-256 релиза awg-openwrt), WireGuard — `mayhem wg-install`. После установки протокола сеть сама перезапускается, если ещё не загрузила его.
- Если на роутере работает другой клиент, перехватывающий трафик, Mayhem установится рядом, но не запустится, пока тот работает.
- uhttpd при установке переводится на соединения без keep-alive (`http_keepalive 0`, один раз и только со значения по умолчанию): иначе Mac с задремавшим Wi‑Fi получает в LuCI «XHR request aborted by browser». Вернуть: `uci set uhttpd.main.http_keepalive=20; uci commit uhttpd; /etc/init.d/uhttpd restart`.

## Интерфейс

LuCI → **Службы → Mayhem**.

**Дашборд**

- Слева — «Список серверов»: в шапке способ выбора сервера (самый быстрый, выбранный вручную, цепочка), текущая скорость и кнопка обновления всех подписок; ниже ключи, туннели и каждая включённая подписка со своим трафиком и сроком. Клик по серверу выбирает его вручную.
- Справа — блок «Информация» (сервер, пинг, внешний IP и местоположение, версии Mayhem и Xray, память xray) и под ним кнопки: способ проверки и «Проверить задержку», «Добавить подключение», «Настройки», перезапуск, остановка или запуск Mayhem, автозапуск. На узком экране — информация, кнопки, затем серверы.
- Значок состояния вверху открывает окно «Службы»: Mayhem, Xray (с причиной последнего перезапуска), dnsmasq.
- Состояние и скорость обновляются раз в 3 секунды, задержки — точечно, без перерисовки страницы.

**Добавить подключение** — окно «Подключения»: «Добавить сервер» (ключи), «Подписки», «Туннели». Ключи, туннели и включённые подписки образуют один «Список серверов». Ключи и подписки применяются по «Сохранить и применить»; новая подписка сразу скачивается и появляется на дашборде.

**Настройки** — вкладки:

| Вкладка | Что там |
| --- | --- |
| Маршрутизация | общие переключатели, KillSwitch, секции и их правила |
| DNS | домашний и удалённый DNS, FakeDNS |
| Геоданные | источники GeoSite/GeoIP |
| Мультиплексирование | Mux для VLESS-серверов |
| Активные подключения | кто куда подключён и каким путём |
| Обновление компонентов | Xray, Mayhem, геоданные, списки, AmneziaWG; автообновление Mayhem |
| Диагностика | проверки служб, ядра, DNS, туннелей и данных; журналы |
| Дополнительно | память xray, сторож, URL-тест, проверка внешнего IP, резервная копия, сброс настроек |

**Командная строка**

```sh
mayhem start|stop|restart       # управление службой
mayhem enable|disable           # включить или выключить маршрутизацию
mayhem status                   # состояние в JSON
mayhem check                    # проверить конфигурацию без применения
mayhem show-config              # показать сгенерированный конфиг xray
mayhem sub-update [ИМЯ]         # обновить подписки сейчас
mayhem geo-update [ИСТОЧНИК]    # скачать геоданные сейчас
mayhem lists-update             # скачать списки сейчас
mayhem killswitch on|off|status # KillSwitch; off сразу снимает удержание выключенного Mayhem
mayhem killswitch hold on|off   # удерживать трафик, пока Mayhem выключен
mayhem xray-install [ВЕРСИЯ]    # переустановить или обновить xray
mayhem self-update [ТЕГ]        # обновить Mayhem до последнего релиза (или ТЕГ)
mayhem auto-update              # то же, если вышел новый релиз и автообновление включено
mayhem awg-install|awg-remove   # установить или удалить AmneziaWG
mayhem wg-install               # установить WireGuard
mayhem tunnel-protos            # перезапустить сеть, если она не загрузила протокол туннеля
mayhem dnsmasq-full             # заменить dnsmasq на dnsmasq-full с откатом при ошибке
mayhem bbr                      # включить TCP BBR
mayhem version                  # версии
```

## Маршрутизация

**Общие переключатели** («Настройки → Маршрутизация»)

- «Глобальный режим»: трафик, не попавший ни под одно правило, идёт через активный сервер списка серверов; выключен — напрямую.
- «Исключить локальные сети из маршрутизации»: 10.0.0.0/8, 192.168.0.0/16 и другие идут напрямую. Адреса VPN-серверов тоже идут напрямую; для доменных адресов серверов обход в ядре использует nftset dnsmasq-full.
- «Пустить трафик роутера через VPN»: TCP самого роутера (обновления пакетов, загрузки, скрипты) подчиняется тем же правилам, его UDP идёт напрямую.
- «Блокировка QUIC (UDP/443)»: браузеры переходят на TCP.
- «Исключить BitTorrent из маршрутизации»: xray распознаёт BitTorrent по первым пакетам и отправляет напрямую.
- «Исключённые IP/MAC источников»: трафик и DNS этих устройств Mayhem не трогает.

**Режим «по спискам»** (глобальный выключен): в xray попадает только трафик правил. Домены прокси-секций получают от dnsmasq адреса из 198.18.0.0/15, подсети их правил сравниваются в ядре; всё остальное, UDP тоже, идёт напрямую в ядре. Устройствам со своим DNS (DoH в браузере, «Частный DNS» на Android) его нужно отключить, иначе сайты из правил пойдут мимо прокси.

**Глобальный режим**: домены секций «напрямую» (UDP тоже) идут мимо xray прямо в ядре — их адреса dnsmasq-full кладёт в набор nftables. Адрес, который исключённый сайт делит с другим (CDN), идёт через xray, и тот различает их по имени.

**Секции**

| Тип | Куда идёт трафик |
| --- | --- |
| Прокси | через серверы xray |
| Туннель | в сетевой интерфейс: AmneziaWG, WireGuard, OpenVPN и любой другой |
| Напрямую | мимо прокси |
| Блокировка | отбрасывается |

Секция — это правило маршрутизации; порядок секций задаёт приоритет. Блокировка проверяется первой, туннели в режиме ядра — сразу после неё.

- **Сервер прокси-секции.** По умолчанию — активный сервер списка серверов. «Подключение» → «Отдельный сервер»: у секции свои ключи и подписки, по желанию фильтр по имени («Дополнительно»). Конкретный сервер закрепляется в поле «Исходящее по умолчанию» — после сохранения в нём доступны серверы секции. Выбор хранится по имени: пока сервер с этим именем есть, секция идёт через него, а если его нет — через самый быстрый из серверов секции.
- **Кого касается.** Прокси-секцию и туннель можно ограничить устройствами (MAC, IP-адрес или подсеть); без выбора секция действует на всю сеть. Туннель в режиме ядра различает устройства и по MAC, xray — только по адресу: устройству, заданному по MAC, нужна аренда DHCP (лучше постоянная).
- **Исключить порты.** В секции «Напрямую» можно указать порты (`4501`, `5000-5100`): TCP и UDP на них идут напрямую к любому адресу, прямо в ядре.
- **Свой DNS.** У секции можно задать свои DNS-серверы (UDP, TCP, DoH или DoQ, по порядку): имена секции спрашиваются у них и через саму секцию. Без них работает DNS со вкладки «DNS». Прокси-секции с FakeDNS свой DNS не нужен.
- **Локальный прокси-порт.** У прокси-секции и туннеля можно включить SOCKS5/HTTP-порт на роутере (с паролем или без), который ведёт в эту секцию. Он доступен с роутера и из сетей Mayhem; с других интерфейсов, например из WAN, подключения отбрасываются.
- Подсети GeoIP секций «напрямую» и «блокировка», локальные адреса и «Исключить порты» обрабатываются в ядре (nftables) в любом режиме. Домены секций «блокировка» отклоняет сам dnsmasq; xray держит только то, что dnsmasq проверить не может (keyword, regexp).

**Правила**

| Запись | Что совпадает |
| --- | --- |
| `example.com` | домен и все поддомены |
| `full:example.com` | только этот домен |
| `keyword:tube` | любой домен с подстрокой |
| `regexp:^ads\.` | регулярное выражение |
| `geosite:youtube`, `geosite:источник:категория` | категория геоданных; `@атрибут` тоже работает |
| `91.108.4.0/22`, `2001:db8::/32` | адреса и подсети IPv4/IPv6 |
| `geoip:ru`, `geoip:!ru` | категория GeoIP или всё, кроме неё |

Правила можно вписать текстом или списком, брать из списков по URL (обновляются автоматически) и из файлов на роутере: одно правило на строку.

**Геоданные**

- По умолчанию GeoSite и GeoIP от [runetfreedom](https://github.com/runetfreedom/russia-v2ray-rules-dat); можно добавить свои источники по URL или загрузить файл.
- Файл на ~70 МБ разбирается прямо во время скачивания, а сохраняются только категории, которые используют секции.
- В выпадающих списках видны все категории с размерами; тяжёлые (больше 50 000 правил) помечены.
- Новая категория скачивается в течение минуты после сохранения, остальное обновляется ночью. Источник, который никто не использует, не скачивается.

## Серверы и подписки

**Серверы** — `vless://` (Reality, TLS, raw, ws, grpc, httpupgrade, xhttp), `vmess://`, `trojan://`, `ss://` (включая 2022), `socks://`, `http(s)://`, `hysteria2://`, `wireguard://`, outbound Xray в JSON, серверы подписок и туннели. Mux включается для всех VLESS-серверов сразу; с XTLS Vision мультиплексируется только UDP, на XHTTP Mux не ставится.

**Выбор сервера**

- «Самый быстрый» — xray выбирает по URL-тесту (адрес и интервал — в «Дополнительно») по среднему из трёх последних проверок, поэтому выход не прыгает между серверами с близкой задержкой. Когда серверов много, интервал растягивается: в среднем не чаще одной проверки в 2 секунды (150 серверов — раз в 5 минут).
- «Выбранный вручную» — сервер, выбранный на дашборде. Он не меняется сам: если перестал отвечать, секция идёт напрямую (с KillSwitch трафик ждёт) и возвращается на него, как только он снова отвечает.
- «Цепочка резервных» — работает первый отвечающий элемент, элемент выше возвращается, как только снова отвечает. Элемент цепочки — сервер (ключ, туннель, сервер подписки) или подписка целиком по её правилу: самый быстрый из её серверов, её собственная цепочка или выбранный в ней сервер.
- Ручная смена сервера идёт на лету через API Xray, без перезапуска; старые соединения сразу сбрасываются. Если в файрволе включено ускорение потоков (flow offloading), уже открытые соединения идут прежним путём, пока не закроются; диагностика об этом предупреждает.
- Проверка серверов — раз в 20 секунд, для всех секций одним проходом: текущий сервер — 5 секунд, не ответивший проверяется ещё раз вместе с кандидатами на замену. Выбор переживает перезагрузку.
- На дашборде у каждого сервера три проверки: URL-тест через сервер, TCP (время соединения, как в v2rayNG) и ICMP. URL-тест идёт по заранее открытым соединениям: пока дашборд открыт, роутер держит соединение через каждый сервер (до 64) и раз в 10 секунд отправляет по нему запрос.

**Подписки**

- Формат определяется сам: список ссылок (обычный или base64) или JSON-конфиг Xray. Ссылку на страницу файла на GitHub или GitLab можно вставлять как есть. Clash YAML не поддерживается.
- Запросы выглядят как от Happ: `User-Agent`, `x-hwid`, `x-device-os`, `x-ver-os`, `x-device-model`, `x-device-locale`. HWID генерируется при установке и редактируется; профиль устройства общий, но его можно переопределить для подписки.
- Показываются название, трафик и срок действия подписки и предупреждение о лимите устройств.
- Обновление раз в 12 часов или с заданным интервалом; скачивание через активный сервер, а если не получилось — напрямую (можно только напрямую). Ответ больше 10 МБ не принимается.
- Подписку можно переименовать: её серверы, место в цепочке и выбранный сервер сохраняются. Серверы можно убирать по названию регулярным выражением и вернуть удалённые.
- Сервер подписки можно переименовать и отредактировать тем же JSON-редактором, что и ключи; правка хранится по исходному имени и переживает обновление подписки.
- Новые серверы применяются без перезапуска xray, кроме изменений XHTTP: тогда xray перезапускается, чтобы освободить транспортные пулы.

## Туннели

- Импорт `.conf` или ключа AmneziaVPN (`vpn://`) создаёт интерфейс без маршрута по умолчанию и зону файрвола. Туннель можно назвать и переименовать его интерфейс — зона файрвола и ссылки в Mayhem поменяются вместе с ним.
- Каждый туннель — сервер в списке серверов: его выбирают на дашборде или его берёт автовыбор. Отключить это для туннеля: `uci set mayhem.<интерфейс>=tunnel; uci set mayhem.<интерфейс>.server=0`.
- Туннель, выбранный на дашборде вручную, получает остальной трафик прямо в ядре, мимо xray (нужен dnsmasq-full); исключения, блокировки, QUIC и BitTorrent при этом работают.
- Весь трафик в туннель, кроме исключений: выберите туннель в «Списке серверов» и включите «Глобальный режим». С «Исключить BitTorrent» ядром в туннель идёт только веб-трафик (TCP 80/443, UDP 443), остальное — через xray.
- Секция-туннель: режим «Ядро» (по умолчанию) — адреса доменов секции dnsmasq-full кладёт в наборы nftables, трафик идёт в туннель из ядра; режим «Через xray» — работают все правила.
- Если у туннеля нет handshake 3 минуты, его трафик идёт напрямую, пока он не восстановится (с KillSwitch — ждёт). Если у туннеля нет IPv6, для его доменов не выдаются IPv6-адреса.

## DNS

- Прямой трафик резолвит домашний DNS (по умолчанию — DNS провайдера), домены прокси-секций и туннелей — удалённый DNS. Удалённые запросы никогда не уходят на домашний DNS.
- Удалённый DNS идёт через активный сервер (можно отключить — тогда напрямую).
- Протоколы: DoH (`https://`), DoQ (`quic://`, всегда напрямую), TCP (`tcp://`), UDP. Есть готовый список публичных резолверов.
- Порядок серверов меняется перетаскиванием: первый — основной, остальные — резервные. По желанию запрос уходит всем серверам сразу и берётся первый годный ответ.
- Запросы устройств на порт 53 перехватываются; при перехвате блокируется DoT (853), чтобы Android Private DNS не уходил в обход правил.
- FakeDNS — по желанию, имеет значение только в глобальном режиме.

## Надёжность

- **KillSwitch** (по умолчанию выключен). Выключен: если у секции не отвечает ни один сервер, её трафик идёт напрямую; если не отвечает удалённый DNS, его имена уходят к DNS провайдера (имена FakeDNS остаются за xray). Всё возвращается само, когда сервер или DNS снова отвечают; напрямую — после двух неудачных проверок подряд. Включён: трафик VPN ждёт серверы, DNS, туннель или xray. Секции «напрямую» остаются исключениями: их IP и порты идут напрямую, домены разрешаются домашним DNS через dnsmasq.
- **Удерживать трафик, пока Mayhem выключен** (только с KillSwitch, по умолчанию выключено): трафик VPN не уходит напрямую и при остановке, выключении и после перезагрузки роутера. Снимается, когда Mayhem снова пропускает трафик, или выключением KillSwitch: в «Маршрутизации», `mayhem killswitch off` или кнопкой на жёлтой плашке дашборда. Правила хранятся в `/etc/mayhem/hold`.
- С KillSwitch перехват не снимается при `mayhem restart` и обновлении пакета: трафик ждёт новый xray. `mayhem stop`, `mayhem disable` и удаление пакета снимают перехват всегда.
- Перехват включается только после того, как xray начал слушать порты. Если xray упал, правила снимаются и трафик идёт напрямую, пока procd его не перезапустит (с KillSwitch — ждёт).
- Сервер, который xray не принимает, пропускается, остальные работают; на дашборде — предупреждение с ошибкой xray. Если xray не запускается несколько раз подряд, пауза перед запуском растёт от 5 секунд до 5 минут.
- Применение настроек идёт по очереди. Если в новых настройках ошибка, xray работает на прежних, а ошибка видна на дашборде.
- «Остановить» на дашборде действует до явного запуска: сохранение настроек и выбор сервера не запускают Mayhem снова. После перезагрузки роутера автозапуск работает как обычно.
- Сторож (включён по умолчанию) перезапускает xray, если тот 3 минуты подряд держит больше заданной доли ОЗУ или не отвечает, и dnsmasq, если тот упал. xray перезапускается на месте, перехват не снимается.
- Память xray: мягкий лимит `GOMEMLIMIT` и `GOGC=50` (`settings.gogc`, 10–400); раз в минуту Mayhem просит xray отдать освобождённую память, если её больше 8 МБ.
- Правила nftables и файл dnsmasq пересобираются только при изменении секций, настроек, геоданных или списков; перезапуск, новые серверы и обновление подписок их не трогают. Во флеш при запуске ничего не пишется.
- Автообновление Mayhem (по умолчанию выключено): раз в сутки, в час ночного обновления, ставится новый релиз вместе с его версией xray.
- IP-адреса на дашборде, в диагностике и журналах замаскированы (`185.*.*.*`); значок глаза показывает их, выбор запоминается в браузере.

## Устройство

```
LAN ─► nftables (inet mayhem) ─┬─ локальные адреса ───────────────► напрямую
                               ├─ блок по IP ─────────────────────► drop
                               ├─ туннели в режиме ядра (метка) ──► awg0 …
                               ├─ исключения по IP ───────────────► напрямую (ядро)
                               └─ остальное ── TPROXY ─► xray ─┬─► прокси-секции, туннели
                                                               ├─► напрямую
                                                               └─► блок
dnsmasq ─► xray DNS (127.0.0.1:12753) ─► домашний / удалённый DNS
        └─► наборы nftables туннелей (dnsmasq-full)
```

Пакеты собираются в GitHub Actions через OpenWrt SDK (24.10 — ipk, 25.12 — apk); при пуше тега `v*` они публикуются в релиз.
