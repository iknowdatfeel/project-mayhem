# Project Mayhem

Маршрутизация трафика для OpenWrt на базе [Xray](https://github.com/XTLS/Xray-core): нужное идёт через прокси, остальное — напрямую. Лёгкий интерфейс в LuCI, установка одной командой.

> Статус: этап 2 из 5. Готовы перехват трафика, секции с правилами, раздельный DNS, серверы по ссылке или JSON, подписки, автоматический и ручной выбор сервера, три вида проверки задержки и дашборд. Geo-данные, AmneziaWG и диагностика — в следующих этапах.

## Требования

- OpenWrt 24.10 (opkg) или 25.12 и новее (apk).
- Около 40 МБ свободной флеш-памяти: сам xray весит ~36 МБ в распакованном виде.
- 128 МБ ОЗУ и больше; рекомендуется 256 МБ.
- Архитектуры: aarch64, arm (v5–v7), mips, mipsel, mips64, x86_64, i386, riscv64.

## Установка

```sh
sh <(wget -O - https://raw.githubusercontent.com/iknowdatfeel/project-mayhem/main/install.sh)
```

Установщик проверяет версию OpenWrt и свободное место, ставит пакеты `mayhem` и `luci-app-mayhem`, скачивает официальный xray нужной архитектуры (с проверкой SHA-256) и оставляет Mayhem выключенным. Повторный запуск обновляет установленную версию.

Если на роутере уже работает другой клиент, перехватывающий трафик, Mayhem установится рядом, но не запустится, пока тот клиент работает.

## Как пользоваться

LuCI → **Службы → Mayhem** (интерфейс пока на английском, русский перевод — в этапе 5):

1. **Подписки** — добавьте ссылку на подписку (необязательно).
2. **Секции** — добавьте секцию, укажите серверы (ссылки или подписки) и перечислите домены и адреса.
3. **Настройки** — выберите режим и DNS, включите маршрутизацию.
4. **Дашборд** — состояние службы, активный сервер каждой секции, задержки, трафик, память xray, подписки.

Командная строка:

```sh
mayhem status          # состояние в JSON
mayhem check           # проверить конфигурацию без применения
mayhem show-config     # показать сгенерированный конфиг xray
mayhem sub-update [ИМЯ] # обновить подписки сейчас
mayhem enable|disable  # включить или выключить маршрутизацию
mayhem xray-install    # переустановить или обновить xray
```

## Возможности

**Режимы**

- «Только списки»: в секции уходит то, что совпало с их правилами, остальное — напрямую.
- «Всё через прокси»: всё уходит в секцию по умолчанию, кроме исключений.

**Секции** — proxy (через сервер), exclusion (напрямую), block (отбросить). Порядок секций задаёт приоритет, блокировка всегда проверяется первой.

**Серверы** — ссылки `vless://` (Reality, TLS, raw, ws, grpc, httpupgrade, xhttp), `vmess://`, `trojan://`, `ss://` (включая 2022), `socks://`, `http(s)://`, `hysteria2://`, `wireguard://`, либо готовый outbound Xray в JSON. Mux можно включить один раз для всех VLESS-серверов; с XTLS Vision мультиплексируется только UDP.

**Несколько серверов в секции** — ссылки и серверы из подписок можно смешивать. Для подписок есть фильтр и исключение по имени сервера (регулярные выражения).

- «Автоматически» — xray сам выбирает самый быстрый сервер по URL-тесту (адрес и интервал проверки задаются в настройках).
- «Вручную» — используется сервер, выбранный на дашборде.
- Сервер можно переключить на дашборде в любой момент, без перезапуска; выбор сохраняется и переживает перезагрузку. В автоматическом режиме выбранный сервер закрепляется, пока не нажата кнопка «Back to automatic».

**Проверка серверов** — на дашборде у каждого сервера три кнопки: URL-тест (HTTP-запрос через этот сервер), TCP (время соединения с сервером) и ICMP (ping).

**Подписки**

- Форматы: список ссылок (обычный или base64) и JSON-конфиг Xray. Clash YAML не поддерживается.
- Запросы выглядят как от Happ: `User-Agent`, `x-hwid`, `x-device-os`, `x-ver-os`, `x-device-model`, `x-device-locale`, плюс свои заголовки. HWID генерируется при установке и редактируется вручную; профиль устройства общий, но для каждой подписки его можно переопределить.
- Показываются название, трафик и срок действия подписки (`subscription-userinfo`, `profile-title`) и предупреждение о лимите устройств.
- Обновление по интервалу из `profile-update-interval`, иначе раз в 12 часов; при ошибке — повтор через 15 минут, старые серверы остаются.
- Скачивание: сначала напрямую, при неудаче — через секцию (по умолчанию), либо только напрямую, либо только через секцию.
- Сохранённая копия подписки во флеш-памяти перезаписывается только когда изменились серверы.

**Правила**

| Запись | Что совпадает |
| --- | --- |
| `example.com` | домен и все поддомены |
| `full:example.com` | только этот домен |
| `keyword:tube` | любой домен с подстрокой |
| `regexp:^ads\.` | регулярное выражение |
| `91.108.4.0/22`, `2001:db8::/32` | адреса и подсети IPv4/IPv6 |

Адреса из секций «напрямую» и «блок» обрабатываются прямо в ядре (nftables) и не проходят через xray.

**DNS**

- Прямой трафик резолвит домашний DNS (по умолчанию — DNS провайдера), домены прокси-секций — удалённый DNS.
- У обоих можно задать резервные серверы; удалённые запросы никогда не уходят на домашний DNS.
- Удалённый DNS может идти напрямую или через выбранную секцию.
- Устройства со своим DNS (8.8.8.8 и т. п.) тоже обслуживаются: запросы на порт 53 перехватываются.
- Протоколы: DoH (`https://`), TCP (`tcp://`), UDP. DoT в Xray нет.
- FakeDNS — по желанию, по умолчанию выключен.

**Надёжность**

- Перехват включается только после того, как xray начал слушать порты.
- Если xray упал, правила сразу снимаются и трафик идёт напрямую, пока procd его не перезапустит.
- Для xray задаётся мягкий лимит памяти (`GOMEMLIMIT`, по умолчанию четверть ОЗУ).
- Ничего не пишется во флеш при запуске: перенаправление dnsmasq живёт в `/tmp`.

## Устройство

```
LAN ─► nftables (inet mayhem) ─┬─ локальные адреса, исключения ──► напрямую (ядро)
                               ├─ блок по IP ──────────────────► drop
                               └─ остальное ── TPROXY ─► xray ─┬─► секции (прокси)
                                                               ├─► напрямую
                                                               └─► блок
dnsmasq ─► xray DNS (127.0.0.1:12753) ─► домашний / удалённый DNS
```

`tests/netns.sh` поднимает клиент, роутер и «интернет» в отдельных сетевых пространствах, запускает настоящий xray и проверяет маршрутизацию, DNS, поведение при падении xray, загрузку подписки с заголовками Happ, автоматический и ручной выбор сервера, переключение с дашборда, проверки задержки и скачивание подписки через секцию.

Пакеты собираются в GitHub Actions через OpenWrt SDK (24.10 — ipk, 25.12 — apk); при пуше тега `v*` они публикуются в релиз.
