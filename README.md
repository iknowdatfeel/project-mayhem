Маршрутизация трафика для OpenWrt на базе [Xray](https://github.com/XTLS/Xray-core): нужное идёт через прокси или туннель либо режим глобального проксирования когда все кроме исключений проксируется, остальное — напрямую. Лёгкий интерфейс в LuCI на русском и английском, установка одной командой.

## Требования

- OpenWrt 24.10 (opkg) или 25.12 и новее (apk).
- Около 40 МБ свободной флеш-памяти: сам xray весит ~36 МБ в распакованном виде.
- 128 МБ ОЗУ и больше; рекомендуется 256 МБ.
- Архитектуры: aarch64, arm (v5–v7), mips, mipsel, mips64, x86_64, i386, riscv64.

## Установка

```sh
sh <(wget -O - https://raw.githubusercontent.com/iknowdatfeel/project-mayhem/main/install.sh)
```

Установщик проверяет версию OpenWrt и свободное место, ставит пакеты `mayhem` и `luci-app-mayhem`, предлагает русский язык интерфейса, скачивает официальный xray нужной архитектуры (с проверкой SHA-256) и оставляет Mayhem выключенным. Повторный запуск обновляет установленную версию. Пакеты AmneziaWG тоже сверяются с SHA-256, который GitHub публикует для файлов релиза awg-openwrt.

Если на роутере уже работает другой клиент, перехватывающий трафик, Mayhem установится рядом, но не запустится, пока тот клиент работает.

Установщик (и обновление Mayhem из меню) заменяет dnsmasq на dnsmasq-full — тот же dnsmasq с поддержкой nftset для туннелей в режиме ядра; если замена не удалась, остаётся прежний dnsmasq. AmneziaWG, WireGuard и обфускаторы WireGuard ставятся отдельно, когда понадобятся: кнопками на странице «Обновление компонентов» или командами `mayhem awg-install`, `mayhem wg-install`, `mayhem obfs-install`; после установки протокола сеть сама перезапускается, если ещё не загрузила его.

## Как пользоваться

LuCI → **Службы → Mayhem**:

1. **Список серверов** — вкладки «Добавить сервер» (ключи vless://, ss:// и другие), «Подписки» (с данными устройства для провайдеров с лимитом устройств), «Туннели» (AmneziaWG, WireGuard и другие интерфейсы) и «Дополнительно» (Mux). Серверы по ключам, туннели и все включённые подписки образуют один «Список серверов», как в Happ; его активный сервер выбирается на дашборде. Серверы подписки можно убирать по названию регулярным выражением.
2. **Маршрутизация** — общие переключатели (остальной трафик через туннель, локальные адреса мимо маршрутизации, отключение QUIC, торренты напрямую), секции с серверами и правилами: домены, адреса, категории GeoSite/GeoIP, списки. Правила можно вписать текстом или списком, секцию можно переименовать. Вкладки DNS и «Геоданные».
3. **Обновление компонентов** — xray, Mayhem, геоданные, списки; автообновление Mayhem.
4. **Настройки** — уровень журнала, память xray, сторож, проверка серверов, сброс к настройкам по умолчанию.
5. **Дашборд** — «Список серверов» одной рамкой: сверху выбор сервера (самый быстрый, выбранный вручную, цепочка), ниже ключи и туннели, каждая подписка со своим трафиком и сроком и туннели для правил; клик по любому серверу выбирает его вручную. Кнопка «Активные подключения» показывает, какое устройство куда подключено (домен, если его адрес пришёл в ответе DNS через Xray, иначе IP), по какому протоколу и каким путём (сервер, туннель, напрямую, DNS, блокировка), сколько соединений и трафика, со счётчиками TCP и UDP; IPv6-устройства подписаны по MAC. Состояние подключения (активный сервер, скорость, пинг, внешний адрес со страной и городом), система, службы. Сбоку кнопки: проверка задержки, обновление серверов, диагностика всего пути трафика, логи, резервная копия настроек (с подписками и ключами или без), перезапуск, остановка и автозапуск.

Командная строка:

```sh
mayhem status           # состояние в JSON
mayhem check            # проверить конфигурацию без применения
mayhem show-config      # показать сгенерированный конфиг xray
mayhem sub-update [ИМЯ] # обновить подписки сейчас
mayhem geo-update [ИСТОЧНИК] # скачать геоданные сейчас
mayhem lists-update     # скачать списки сейчас
mayhem enable|disable   # включить или выключить маршрутизацию
mayhem xray-install     # переустановить или обновить xray
mayhem self-update      # обновить Mayhem до последней версии
mayhem auto-update      # то же, если вышла новая версия и автообновление включено
mayhem awg-install      # установить AmneziaWG (сборки awg-openwrt под эту прошивку)
mayhem dnsmasq-full     # заменить dnsmasq на dnsmasq-full с откатом при ошибке
mayhem obfs-install phobos|faketcp # установить обфускатор WireGuard
```

## Возможности

**Основная секция**

- Основная секция — всегда «Список серверов»: через его активный сервер идут удалённый DNS и загрузка подписок, геоданных и списков.
- «Глобальный режим»: трафик, не попавший ни под одно правило, уходит через активный сервер основной секции; если выключено — напрямую. В глобальном режиме трафик доменов из секций «напрямую» (UDP тоже) идёт мимо xray прямо в ядре: их адреса dnsmasq-full кладёт в набор nftables. Адрес, который исключённый сайт делит с другим (CDN), идёт через xray, и тот различает их по имени.
- Локальные адреса (10.0.0.0/8, 192.168.0.0/16 и другие) по умолчанию не маршрутизируются.
- По желанию: отключить QUIC (UDP 443 отбрасывается, браузеры переходят на TCP) и пропускать торренты напрямую (xray распознаёт BitTorrent по первым пакетам).

**Секции**

| Тип | Куда идёт трафик |
| --- | --- |
| Прокси | через серверы xray |
| Туннель | в сетевой интерфейс: AmneziaWG, WireGuard, OpenVPN и любой другой |
| Напрямую | мимо прокси |
| Блокировка | отбрасывается |

Секция — это правило маршрутизации. Прокси-секция по умолчанию ведёт свой трафик через активный сервер списка серверов; для отдельных доменов в ней можно задать отдельный сервер (ключи, подписки, фильтр по имени). Порядок секций задаёт приоритет. Блокировка всегда проверяется первой, туннели в режиме ядра — сразу после неё.

- **Кого касается.** Прокси-секцию и туннель можно ограничить выбранными устройствами (MAC, IP-адрес или подсеть); если ничего не выбрано, секция действует на всю сеть. Остальные устройства идут к секциям ниже. Туннель в режиме ядра различает устройства и по MAC, xray — только по адресу: устройству, заданному по MAC, нужна аренда DHCP (лучше постоянная).
- **Исключить порты.** В секции «Напрямую» можно указать порты (`4501`, `5000-5100`): TCP и UDP на них идут напрямую к любому адресу, прямо в ядре. Домены и адреса самой секции при этом идут напрямую на любом порту.
- **Свой DNS.** У секции можно задать свои DNS-серверы (UDP, TCP, DoH или DoQ, по порядку): имена секции спрашиваются у них и через саму секцию. Если ничего не выбрано, работает DNS со вкладки «DNS». Прокси-секции с FakeDNS свой DNS не нужен: имена разрешает её сервер.

**Серверы** — ссылки `vless://` (Reality, TLS, raw, ws, grpc, httpupgrade, xhttp), `vmess://`, `trojan://`, `ss://` (включая 2022), `socks://`, `http(s)://`, `hysteria2://`, `wireguard://`, готовый outbound Xray в JSON, серверы из подписок и сетевые интерфейсы (туннель как обычный сервер группы). Mux можно включить один раз для всех VLESS-серверов; с XTLS Vision мультиплексируется только UDP, на XHTTP Mux не ставится (у него своё мультиплексирование).

**Выбор сервера**

- «Самый быстрый» — xray сам выбирает самый быстрый сервер по URL-тесту (адрес и интервал проверки задаются в настройках); в «Списке серверов» — среди всех ключей, туннелей и подписок.
- «Выбранный вручную» — используется сервер, выбранный на дашборде; в «Списке серверов» в этот режим переводит клик по любому серверу.
- «Цепочка резервных» — работает первый отвечающий элемент цепочки, элемент выше возвращается, как только снова отвечает (проверка раз в 20 секунд). В цепочке «Списка серверов» элемент — сервер (ключ, туннель, сервер подписки) или подписка целиком по её правилу: самый быстрый из её серверов, её собственная цепочка или выбранный в ней сервер. Правило подписки задаётся в окне цепочки, на дашборде у подписки значок с её местом в цепочке.
- Смена режима, сервера и цепочки — без перезапуска xray.
- В секции можно задать сервер по умолчанию; в любом случае сервер можно переключить на дашборде в любой момент, без перезапуска; выбор сохраняется и переживает перезагрузку.
- На дашборде у каждого сервера три проверки: URL-тест через этот сервер, TCP (время соединения) и ICMP (ping).
- URL-тест на дашборде идёт по заранее открытым соединениям: пока дашборд открыт, роутер держит соединение через каждый сервер (до 64) и раз в 10 секунд отправляет по нему запрос, поэтому задержка видна сразу и остаётся свежей. Считается время запроса по уже открытому соединению, без рукопожатий. Закрыли дашборд — через минуту соединения закрываются; при следующем открытии сразу видны последние числа (до 30 минут), пока не придут новые. Нужен пакет `ucode-mod-socket` (ставится вместе с Mayhem).
- TCP-пинг — время одного соединения до сервера, как в v2rayNG; серверы секции проверяются одним запросом, волнами по 16, к одному адресу — по очереди. ICMP-пинг всех серверов секции тоже идёт одним запросом, параллельно.

**Подписки**

- Формат определяется сам: список ссылок (обычный или base64) или JSON-конфиг Xray. Ссылку на страницу файла на GitHub или GitLab можно вставлять как есть. Clash YAML не поддерживается.
- Запросы выглядят как от Happ: `User-Agent`, `x-hwid`, `x-device-os`, `x-ver-os`, `x-device-model`, `x-device-locale`. HWID генерируется при установке и редактируется вручную; профиль устройства общий, но для каждой подписки его можно переопределить.
- Показываются название, трафик и срок действия подписки и предупреждение о лимите устройств.
- Обновление раз в 12 часов или с заданным интервалом; скачивание через активный сервер основной секции, а если не получилось — напрямую (можно скачивать только напрямую).
- Копия подписки во флеш-памяти перезаписывается только когда изменились серверы.
- Новые серверы подписки применяются в работающем xray без перезапуска: соединения не рвутся, а через сервер, который пропал из подписки, доживают до конца. xray перезапускается, только если изменилось что-то кроме серверов (правила, DNS, geo-файлы).

**Правила**

| Запись | Что совпадает |
| --- | --- |
| `example.com` | домен и все поддомены |
| `full:example.com` | только этот домен |
| `keyword:tube` | любой домен с подстрокой |
| `regexp:^ads\.` | регулярное выражение |
| `geosite:youtube`, `geosite:источник:категория` | категория геоданных; `@атрибут` тоже работает |
| `91.108.4.0/22`, `2001:db8::/32` | адреса и подсети IPv4/IPv6 |
| `geoip:ru`, `geoip:!ru` | категория GeoIP или всё, кроме неё |

Правила можно брать из списков по URL (обновляются автоматически) и из файлов на роутере: один домен, правило или подсеть на строку.

**Geo-данные**

- По умолчанию GeoSite и GeoIP от [runetfreedom](https://github.com/runetfreedom/russia-v2ray-rules-dat); можно добавить свои источники по URL или загрузить файл.
- Файл на ~70 МБ не помещается на флеш роутера, поэтому он разбирается прямо во время скачивания, а сохраняются только категории, которые используют секции: несколько сотен килобайт.
- В выпадающих списках видны все категории с размерами; тяжёлые (больше 50 000 правил) помечены.
- Новая категория скачивается в течение минуты после сохранения, остальное обновляется ночью. Источник, который никто не использует, не скачивается.
- В режиме «по спискам» в xray попадает только трафик правил: домены прокси-секций получают от dnsmasq адреса из 198.18.0.0/15, подсети их правил сравниваются в ядре. Всё остальное, UDP тоже, идёт напрямую в ядре, мимо xray. Устройствам со своим DNS (DoH в браузере, «Частный DNS» на Android) его нужно отключить, иначе сайты из правил пойдут мимо прокси.
- Установщик (и при первой установке, и при каждом обновлении) ставит модуль TCP BBR и включает его для соединений роутера: через них xray ходит к своим серверам, и весь проксируемый TCP идёт быстрее на линиях с потерями. Если в прошивке модуля нет, всё остаётся как было (`mayhem bbr`).
- Подсети GeoIP у секций «напрямую» и «блокировка», локальные адреса и «Исключить порты» обрабатываются в ядре (nftables) и не проходят через xray в любом режиме.
- Домены секций «блокировка» (и категории GeoSite в них) отклоняет сам dnsmasq: заблокированный адрес сразу не находится, и устройство не ждёт оборванного соединения; xray держит только то, что dnsmasq проверить не может (keyword, regexp).

**Туннели (AmneziaWG и другие)**

- Импорт `.conf` или ключа AmneziaVPN (`vpn://`) создаёт интерфейс без маршрута по умолчанию и зону файрвола. Каждый туннель (AmneziaWG, WireGuard, OpenVPN и др.) — сервер в списке серверов: его выбирают на дашборде, как VLESS, или его берёт автовыбор по пингу; отключить это для отдельного туннеля — `uci set mayhem.<интерфейс>=tunnel; uci set mayhem.<интерфейс>.server=0`. Секцию маршрутизации для туннеля можно создать по желанию.
- Туннель, выбранный на дашборде вручную, получает остальной трафик прямо в ядре, мимо xray (нужен dnsmasq-full): xray держит только то, что идёт в прокси-секции, и почти не тратит память. Исключения, блокировки, «Блокировка QUIC» и «Исключить BitTorrent из маршрутизации» при этом работают. Без dnsmasq-full трафик туннеля идёт через xray.
- У туннеля можно задать название (его видно на дашборде) и переименовать интерфейс — зона файрвола и все ссылки в Mayhem поменяются вместе с ним.
- **Обфускация WireGuard/AmneziaWG** (в окне редактирования туннеля, на выбор):
  - **Phobos (wg-obfuscator)** — пакеты шифруются ключом (XOR) и при желании маскируются под STUN; на сервере перед WireGuard нужен [wg-obfuscator](https://github.com/ClusterM/wg-obfuscator) с тем же ключом.
  - **Phantun (wg-phantun)** — UDP туннеля идёт к серверу как TCP-соединение, для сетей, где режут или душат UDP; на сервере перед WireGuard нужен `phantun_server` ([phantun](https://github.com/dndx/phantun)), MTU туннеля снижается до 1428.
  Endpoint пира переключается на локальный обфускатор (`127.0.0.1`), в `.conf` по-прежнему виден настоящий сервер. Обфускатор ставится кнопкой в том же окне или командой `mayhem obfs-install phobos|faketcp` (статическая сборка из релиза на GitHub, с проверкой SHA-256) и работает отдельной службой `mayhem-obfs`, независимо от того, включена ли маршрутизация.
- Режим «Ядро» (по умолчанию): адреса доменов секции dnsmasq-full кладёт в наборы nftables, трафик идёт в туннель прямо из ядра — быстрее всего, без xray.
- Весь трафик в туннель, кроме исключений: выберите туннель в «Списке серверов» (вручную или первым в цепочке) и включите «Глобальный режим». Тогда всё, что не попало в правила, уходит в туннель прямо из ядра, мимо xray. Исключения (например, `geoip:ru` в секции «напрямую») идут напрямую, блокировки блокируются, прокси-секции работают через xray. Для исключений и прокси-секций по доменам нужен dnsmasq-full. «Блокировка QUIC» работает и здесь; если включено «Исключить BitTorrent из маршрутизации», ядром в туннель идёт только веб-трафик (TCP 80/443, UDP 443), остальное — через xray, который отправляет торренты напрямую.
- Режим «Через xray»: работают все правила; туннель можно добавить сервером в прокси-секцию и переключаться между ним и VLESS автоматически.
- Если туннель не работает (нет handshake 3 минуты), трафик секции идёт напрямую, пока он не восстановится (с KillSwitch — ждёт его).
- Если у туннеля нет IPv6, для его доменов не выдаются IPv6-адреса.

**DNS**

- Прямой трафик резолвит домашний DNS (по умолчанию — DNS провайдера), домены прокси-секций и туннелей — удалённый DNS.
- У обоих можно задать резервные серверы; удалённые запросы никогда не уходят на домашний DNS.
- Удалённый DNS идёт через активный сервер (можно отключить — тогда напрямую, DoH остаётся зашифрованным).
- Для обоих есть готовый список публичных резолверов: Cloudflare, Google, Quad9, AdGuard, Яндекс, Comss DNS, Xbox DNS.
- Устройства со своим DNS (8.8.8.8 и т. п.) тоже обслуживаются: запросы на порт 53 перехватываются.
- Протоколы: DoH (`https://`), DoQ (`quic://`, всегда напрямую, мимо прокси), TCP (`tcp://`), UDP. DoT в Xray нет.
- Порядок серверов меняется перетаскиванием: первый — основной, остальные — резервные. По желанию «Спрашивать серверы сразу все»: запрос уходит всем серверам списка и берётся первый годный ответ.
- FakeDNS — по желанию, по умолчанию выключен; имеет значение только в «Глобальном режиме».

**Скрытие IP-адресов** — внешний адрес на дашборде, результаты диагностики и логи показывают IP-адреса замаскированными (`185.*.*.*`); значок глаза рядом показывает их везде, выбор запоминается в браузере.

**Локальный прокси-порт** — у прокси-секции и туннеля можно включить SOCKS5/HTTP-порт на роутере (с паролем или без), который ведёт в эту секцию.

**Надёжность**

- Сервер, выбранный на дашборде вручную, начинает работать сразу и для уже открытых соединений: xray перезапускается под теми же правилами перехвата (трафик в эти секунды не уходит напрямую), и приложения переподключаются через новый сервер. Раньше браузер продолжал ходить через старый сервер, пока не закрывал соединение.
- Серверы переименовываются на дашборде (✎ на карточке) и в списке ключей: имя ключа — прямо в ключе, сервера подписки — в настройках подписки (переживает её обновления), туннеля — в его названии.
- Перехват включается только после того, как xray начал слушать порты.
- Если xray упал, правила сразу снимаются и трафик идёт напрямую, пока procd его не перезапустит (с включённым KillSwitch — ждёт xray).
- Веб-интерфейс роутера: при установке uhttpd переводится на соединения без keep-alive (`http_keepalive 0`, один раз и только со значения по умолчанию). Иначе Mac с задремавшим Wi‑Fi не замечает, что роутер закрыл простаивающее соединение, и LuCI на любой странице показывает «XHR request aborted by browser». Вернуть: `uci set uhttpd.main.http_keepalive=20; uci commit uhttpd; /etc/init.d/uhttpd restart`.
- **KillSwitch** («Маршрутизация», по умолчанию выключен). Выключен: если у секции не отвечает ни один сервер (у цепочки резервных — все серверы цепочки), её трафик идёт напрямую; если не отвечает удалённый DNS, имена, которым он нужен, уходят к DNS провайдера (имена с адресами FakeDNS остаются за xray). Mayhem при этом не выключается, а когда сервер или DNS снова отвечают, всё возвращается само. Проверка — раз в 20 секунд, напрямую после двух неудачных проверок подряд. Включён: ничего не уходит напрямую — ни при лежащих серверах и DNS, ни при упавшем туннеле, ни пока xray перезапускается; трафик ждёт.
- Сторож (включён по умолчанию) перезапускает xray, если тот 3 минуты подряд держит больше 40% ОЗУ, и dnsmasq, если тот упал; если dnsmasq не стартует с настройками Mayhem, они снимаются.
- Если xray перезапускался, в «Состоянии подключения» 10 минут видно, когда и почему: изменились настройки (какие части: DNS, входящие порты, маршрутизация…), обновились геоданные, серверы не удалось сменить на лету, сторож, перезапуск вручную или xray завершился сам (с кодом). Если xray не запускается из-за конфига (например, regexp, который не понимает Go), его собственная ошибка видна на дашборде.
- Для xray задаётся мягкий лимит памяти (`GOMEMLIMIT`, по умолчанию четверть ОЗУ) и `GOGC=50`: память закрытых соединений возвращается системе раньше (`settings.gogc`, 10–400). Раз в минуту, если освобождённой, но не отданной памяти больше 8 МБ, Mayhem просит xray собрать мусор сразу.
- Каждый UDP-поток в xray — около 35 КБ памяти. Потоки, которые идут напрямую, закрываются через 45–90 с после последнего пакета, а не через 2–3 минуты (TCP — как обычно, через 5 минут).
- Серверы с автовыбором проверяются по одному, в случайный момент интервала; все сразу — только при запуске. При одновременной проверке 150 серверов xray брал на каждой проверке до 20 МБ сверху. Когда серверов много, интервал растягивается: не меньше двух секунд на сервер (150 серверов — раз в 5 минут).
- Ничего не пишется во флеш при запуске: перенаправление dnsmasq живёт в `/tmp`, кэши — в ОЗУ.
- Автообновление Mayhem (по желанию, выключено по умолчанию): раз в сутки в час ночного обновления ставится новый релиз вместе с его версией xray; автозапуск и состояние службы сохраняются.

## Устройство

```
LAN ─► nftables (inet mayhem) ─┬─ локальные адреса ───────────────► напрямую
                               ├─ блок по IP ─────────────────────► drop
                               ├─ туннели в режиме ядра (метка) ──► awg0 …
                               ├─ исключения по IP ───────────────► напрямую (ядро)
                               └─ остальное ── TPROXY ─► xray ─┬─► прокси-секции, туннели
                                                               ├─► напрямую
                                                               └─► блок
dnsmasq ─► xray DNS (127.0.0.1:12753) ─► домашний / удалённый DNS
        └─► наборы nftables туннелей (dnsmasq-full)
```

Пакеты собираются в GitHub Actions через OpenWrt SDK (24.10 — ipk, 25.12 — apk); при пуше тега `v*` они публикуются в релиз.
