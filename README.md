Маршрутизация трафика для OpenWrt на базе [Xray](https://github.com/XTLS/Xray-core): нужное идёт через прокси или туннель, остальное — напрямую. Лёгкий интерфейс в LuCI на русском и английском, установка одной командой.

> Статус: все пять этапов реализованы и проходят тесты вне роутера (юнит-тесты, сквозной тест в сетевых пространствах с настоящим xray, проверка страниц LuCI в браузере). На реальном роутере ещё не проверялось.

## Требования

- OpenWrt 24.10 (opkg) или 25.12 и новее (apk).
- Около 40 МБ свободной флеш-памяти: сам xray весит ~36 МБ в распакованном виде.
- 128 МБ ОЗУ и больше; рекомендуется 256 МБ.
- Архитектуры: aarch64, arm (v5–v7), mips, mipsel, mips64, x86_64, i386, riscv64.

## Установка

```sh
sh <(wget -O - https://raw.githubusercontent.com/iknowdatfeel/project-mayhem/main/install.sh)
```

Установщик проверяет версию OpenWrt и свободное место, ставит пакеты `mayhem` и `luci-app-mayhem`, предлагает русский язык интерфейса, скачивает официальный xray нужной архитектуры (с проверкой SHA-256) и оставляет Mayhem выключенным. Повторный запуск обновляет установленную версию.

Если на роутере уже работает другой клиент, перехватывающий трафик, Mayhem установится рядом, но не запустится, пока тот клиент работает.

AmneziaWG и dnsmasq-full ставятся отдельно, когда понадобятся: кнопками на странице «Секции» или командами `mayhem awg-install` и `mayhem dnsmasq-full`.

## Как пользоваться

LuCI → **Службы → Mayhem**:

1. **Подписки** — добавьте ссылку на подписку (необязательно).
2. **Секции** — добавьте секцию, укажите серверы (ссылки, подписки, туннели) и правила: домены, адреса, категории geosite/geoip, списки.
3. **Настройки** — режим, DNS, geo-данные, сторож; включите маршрутизацию.
4. **Дашборд** — состояние службы, активный сервер каждой секции, задержки, трафик, туннели, подписки, geo-данные.
5. **Диагностика** — проверка всего пути трафика и внешний адрес через каждую секцию.
6. **Логи** — сообщения Mayhem, xray и dnsmasq, переключатель уровня логирования.

Командная строка:

```sh
mayhem status           # состояние в JSON
mayhem check            # проверить конфигурацию без применения
mayhem show-config      # показать сгенерированный конфиг xray
mayhem sub-update [ИМЯ] # обновить подписки сейчас
mayhem geo-update [ИСТОЧНИК] # скачать geo-данные сейчас
mayhem lists-update     # скачать списки сейчас
mayhem enable|disable   # включить или выключить маршрутизацию
mayhem xray-install     # переустановить или обновить xray
mayhem awg-install      # установить AmneziaWG (сборки awg-openwrt под эту прошивку)
mayhem dnsmasq-full     # заменить dnsmasq на dnsmasq-full с откатом при ошибке
```

## Возможности

**Режимы**

- «Только списки»: в секции уходит то, что совпало с их правилами, остальное — напрямую.
- «Всё через прокси»: всё уходит в секцию по умолчанию, кроме исключений.

**Секции**

| Тип | Куда идёт трафик |
| --- | --- |
| Прокси | через серверы xray |
| Туннель | в сетевой интерфейс: AmneziaWG, WireGuard, OpenVPN и любой другой |
| Напрямую | мимо прокси |
| Блокировка | отбрасывается |

Порядок секций задаёт приоритет. Блокировка всегда проверяется первой, туннели в режиме ядра — сразу после неё.

**Серверы** — ссылки `vless://` (Reality, TLS, raw, ws, grpc, httpupgrade, xhttp), `vmess://`, `trojan://`, `ss://` (включая 2022), `socks://`, `http(s)://`, `hysteria2://`, `wireguard://`, готовый outbound Xray в JSON, серверы из подписок и сетевые интерфейсы (туннель как обычный сервер группы). Mux можно включить один раз для всех VLESS-серверов; с XTLS Vision мультиплексируется только UDP.

**Выбор сервера**

- «Автоматически» — xray сам выбирает самый быстрый сервер по URL-тесту (адрес и интервал проверки задаются в настройках).
- «Вручную» — используется сервер, выбранный на дашборде.
- Сервер можно переключить на дашборде в любой момент, без перезапуска; выбор сохраняется и переживает перезагрузку.
- На дашборде у каждого сервера три проверки: URL-тест через этот сервер, TCP (время соединения) и ICMP (ping).

**Подписки**

- Форматы: список ссылок (обычный или base64) и JSON-конфиг Xray. Clash YAML не поддерживается.
- Запросы выглядят как от Happ: `User-Agent`, `x-hwid`, `x-device-os`, `x-ver-os`, `x-device-model`, `x-device-locale`, плюс свои заголовки. HWID генерируется при установке и редактируется вручную; профиль устройства общий, но для каждой подписки его можно переопределить.
- Показываются название, трафик и срок действия подписки и предупреждение о лимите устройств.
- Обновление по интервалу из `profile-update-interval`, иначе раз в 12 часов; скачивание напрямую, через секцию или «сначала напрямую, потом через секцию».
- Копия подписки во флеш-памяти перезаписывается только когда изменились серверы.

**Правила**

| Запись | Что совпадает |
| --- | --- |
| `example.com` | домен и все поддомены |
| `full:example.com` | только этот домен |
| `keyword:tube` | любой домен с подстрокой |
| `regexp:^ads\.` | регулярное выражение |
| `geosite:youtube`, `geosite:источник:категория` | категория geo-данных; `@атрибут` тоже работает |
| `91.108.4.0/22`, `2001:db8::/32` | адреса и подсети IPv4/IPv6 |
| `geoip:ru`, `geoip:!ru` | категория geoip или всё, кроме неё |

Правила можно брать из списков по URL (обновляются автоматически) и из файлов на роутере: один домен, правило или подсеть на строку.

**Geo-данные**

- По умолчанию geosite и geoip от [runetfreedom](https://github.com/runetfreedom/russia-v2ray-rules-dat); можно добавить свои источники по URL или загрузить файл.
- Файл на ~70 МБ не помещается на флеш роутера, поэтому он разбирается прямо во время скачивания, а сохраняются только категории, которые используют секции: несколько сотен килобайт.
- В выпадающих списках видны все категории с размерами; тяжёлые (больше 50 000 правил) помечены.
- Новая категория скачивается в течение минуты после сохранения, остальное обновляется ночью. Источник, который никто не использует, не скачивается.
- Подсети geoip у секций «напрямую» и «блокировка» обрабатываются в ядре (nftables) и не проходят через xray.

**Туннели (AmneziaWG и другие)**

- Импорт `.conf` или ключа AmneziaVPN (`vpn://`) создаёт интерфейс без маршрута по умолчанию, зону файрвола и секцию; можно выбрать и уже существующий интерфейс.
- Режим «Ядро» (по умолчанию): адреса доменов секции dnsmasq-full кладёт в наборы nftables, трафик идёт в туннель прямо из ядра — быстрее всего, без xray. То, что DNS-путь пропустил, xray подхватывает по SNI и отправляет в тот же туннель.
- Режим «Через xray»: работают все правила; туннель можно добавить сервером в прокси-секцию и переключаться между ним и VLESS автоматически.
- Если туннель не работает (нет handshake 3 минуты), трафик секции идёт напрямую, пока он не восстановится.
- Если у туннеля нет IPv6, для его доменов не выдаются IPv6-адреса.

**DNS**

- Прямой трафик резолвит домашний DNS (по умолчанию — DNS провайдера), домены прокси-секций и туннелей — удалённый DNS.
- У обоих можно задать резервные серверы; удалённые запросы никогда не уходят на домашний DNS.
- Удалённый DNS может идти напрямую или через выбранную секцию.
- Устройства со своим DNS (8.8.8.8 и т. п.) тоже обслуживаются: запросы на порт 53 перехватываются.
- Протоколы: DoH (`https://`), TCP (`tcp://`), UDP. DoT в Xray нет.
- FakeDNS — по желанию, по умолчанию выключен.

**Локальный прокси-порт** — у прокси-секции и туннеля можно включить SOCKS5/HTTP-порт на роутере (с паролем или без), который ведёт в эту секцию.

**Надёжность**

- Перехват включается только после того, как xray начал слушать порты.
- Если xray упал, правила сразу снимаются и трафик идёт напрямую, пока procd его не перезапустит.
- Сторож (включён по умолчанию) перезапускает xray, если тот 3 минуты подряд держит больше 40% ОЗУ, и dnsmasq, если тот упал; если dnsmasq не стартует с настройками Mayhem, они снимаются.
- Для xray задаётся мягкий лимит памяти (`GOMEMLIMIT`, по умолчанию четверть ОЗУ).
- Ничего не пишется во флеш при запуске: перенаправление dnsmasq живёт в `/tmp`, кэши — в ОЗУ.

## Устройство

```
LAN ─► nftables (inet mayhem) ─┬─ локальные адреса ───────────────► напрямую
                               ├─ блок по IP ─────────────────────► drop
                               ├─ туннели в режиме ядра (метка) ──► awg0 …
                               ├─ исключения по IP ───────────────► напрямую (ядро)
                               └─ остальное ── TPROXY ─► xray ─┬─► прокси-секции, туннели
                                                               ├─► напрямую
                                                               └─► блок
dnsmasq ─► xray DNS (127.0.0.1:12753) ─► домашний / удалённый DNS
        └─► наборы nftables туннелей (dnsmasq-full)
```

Пакеты собираются в GitHub Actions через OpenWrt SDK (24.10 — ipk, 25.12 — apk); при пуше тега `v*` они публикуются в релиз.
